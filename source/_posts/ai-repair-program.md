事情是这样的。

我在开发 ScopeDB 的时候，很自然的遇到了要支持近似计数的需求，也就是 `approx_count_distinct` 的需求。

这种需求典型的解法就是使用 HyperLogLog 数据结构。由于 Rust 生态 HLL 实现参差不齐，起初经过一番调研，我选择了Cloudflare 开源的 [cardinality-estimator](https://github.com/cloudflare/cardinality-estimator) 库。但是，这个库在实现的时候重度使用了 `unsafe` 代码，并且还有各种手工位打包的奇技淫巧。为了代码可控，我不得不在 ScopeDB 里单独 Fork 并维护一份内部版本。

在调研期间，我了解到 Apache DataSketches 有一套久经考验的 HllSketch 实现，以及号称效果更好的 CpcSketch 方案。可惜，当时的 DataSketches 项目只有 Java 和 C++ 实现，而 ScopeDB 是用 Rust 写成的。

好在机缘巧合，我确认了 DataSketches 上游对维护一个 Rust 版本的兴趣。从去年底开始，我跟其他几位对草图算法颇有研究的 Rust 开发者一起开发发布了若干个 datasketches-rust 的版本，其中就包括 HllSketch 的第一版实现。随后，我把 ScopeDB 近似计数的实现切换到了 datasketches-rust 实现的 HllSketch 上。

(一张 https://github.com/apache/datasketches-rust/graphs/contributors?selectedMetric=commits&all=1 的截图)

实现过流式不重复计数算法的开发这大多熟悉 HLL 的原理：它把元素哈希后投进 $K$ 个桶，每个桶**只记录见过的最大前导零个数**（通常占 4 到 6 bit）——同一个桶里后来出现的更小计数，信息就直接丢掉了，而且进入稠密模式后每个桶都要维持固定位宽的寄存器。

Yahoo! Research 的计算机科学家 Kevin J. Lang 在 2017 年的论文 [Back to the Future: an Even More Nearly Optimal Cardinality Estimation Algorithm](https://arxiv.org/pdf/1708.06839) 里提出了一个返璞归真的方案：**直接保留经典 Flajolet–Martin（FM85）「优惠券收集」过程的 $K \times 64$ 位矩阵**（第 $r$ 行每遇到一个前导零数为 $c$ 的哈希，就把矩阵的 $(r, c)$ 位置 1）。保留完整的二维命中记录，让 CPC 能配合流式的 HIP 估计器和可合并的 ICON 估计器拿到比 HLL 更高的统计效率；序列化时，它又根据填充密度自适应切换格式（低基数用稀疏的「意外对」表，中高基数用滑动 8-bit 窗口 + 长度受限的 Huffman 编码 + 列置换），把体积压到接近信息熵。按 DataSketches 官方文档的说法，**同等精度下，序列化后的 CPC 比 HLL 体积缩小百分之三十到四十**。

今年 1 月底，我动手把 CpcSketch 移植到了 datasketches-rust 项目里，随后将 ScopeDB 近似计数的实现也切到了 CPCSketch 上。半年多来，线上相关功能一直跑得很稳。

(一张 https://github.com/apache/datasketches-rust/pull/75 的截图)

不过，在对照上游 C++ 和 Java 源码移植 `CpcSketch` 的时候，我发现源码里存在着一系列硬编码的魔数表：

我在移植一些简单查表模块时，习惯在单元测试里从第一性原理直接算出整张表，再和静态数组逐项比对。比如对于 `kxp_byte_lookup` 表，我通过测试保留了推导这个魔数表的逻辑：

```rust
for byte in 0u8..=255 {
    // expected value
    let expected = KXP_BYTE_TABLE[byte as usize];

    // computed value
    let mut computed = 0.0;
    for col in 0..8 {
        let bit = (byte >> col) & 1;
        if bit == 0 {
            // note the inverted logic
            computed += inv_pow2(col + 1); //note the "+1"
        }
    }

    assert_eq!(expected, computed);
}
```

但是，CpcSketch 当中存在着 `CompressionData` 等几个完全没有推导逻辑的魔数矩阵。上游注释里只留下了两行构建命令：

```shell
~/ocaml-4.03.0/bin/ocamlopt -o generateHuffmanCodes columnProbabilities.ml generateHuffmanCodes.ml
./generateHuffmanCodes > raw-encoding-tables.c
```

我翻遍所有 Apache DataSketches 仓库都找不到这些 `.ml` 文件。于是，我到在 datasketches-java 仓库提了 [Issue-720](https://github.com/apache/datasketches-java/issues/720)）问生成源码在哪。社区负责人老李（Lee Rhodes）回复道：

> Kevin did most of his math simulations and modeling in OCaml. And his code was on his computer, which no longer exists. And his personal code died with him … even if they have a copy of his old computer it might be trying to find a needle in a haystack.

Kevin 已于 2019 年 4 月离世，相关代码或许在他的个人电脑上，但是要在找到原始的代码，恐怕也无异于大海捞针了。

我深表遗憾。但是转年一想，既然运行时解码表的构建逻辑还在，注释里也留有线索，也许我们能从注释和静态表反推出原来的生成程序。于是我继续问老李，论文里有没有记载推导出这些表的细节？对此，老李回复到：

> You should definitely read the paper. But it won't tell you any details on the Huffman codings. As I recall, in his paper he used a more standard compression scheme. He finished his work on the code after he had finished his paper -- and in the process came up with the modified Huffman coding idea, which is quite a bit more efficient than what he discussed in the paper.

这就不是我一下子能看懂的内容了。

由于即使不知道推出魔数表的逻辑，有正确的查找表，datasketches-rust 当中的 CpcSketch 就能正常运行，于是我也就暂时搁下了思考打表的源代码。

直到最近正好赶上 Gemini 4 Carbon 发布，我也正打算发布 datasketches-rust 的下一个版本，这时我突然想到：现在的 LLM AI 应该有能力反推出这些魔数表的构造方法了，要不我试试？

整个过程最后变成了三个模型的接力：

1. **Gemini 4 Carbon** 顺着静态表和源码注释从零反推，搭起了第一版生成器测试：逐位复现了全部码字和置换表，并以相近精度重建了 ICON 多项式拟合；
2. **Claude Opus 5.5** 对初步结论做数学 Review 与证伪：用消融实验推翻了初版的「左边界截断」假说，揪出了一处浮点舍入陷阱，划清了多项式拟合的可辨识边界，还重跑了百万次蒙特卡罗统计；
3. **GPT 6 Astra** 对上面的结果做了一轮交叉审查：用变异测试找出了两处测试保护缺口，纠正了初稿里好几处数学错误和过度推断，还顺手给出了渐近常数最后几位数字的一个精确解释。

当然，实际过程不止一轮，而是几个模型来回复核对齐的交叉合作。最终结果就是 PR-355 以跟上面记录 `kxp_byte_lookup` 表生成逻辑一样的方式，在 datasketches-rust 仓库中以测试的形式记录了逆向工程出来的原始 OCaml 文件的打表逻辑。

## 一、离散码字的盲区，与注释里的 20 位「指纹」

首先是 23 张 Huffman 编码表（见 [`compression_data.rs`](https://github.com/apache/datasketches-rust/blob/main/datasketches/src/cpc/compression_data.rs)）。

为什么 CPC 要存 23 张静态 Huffman 表？如果在运行时动态建树，序列化时就得把树结构一起写进字节流，小 Sketch 好不容易省下来的几十个字节会被表头吃光。而位矩阵第 $j$ 列被置 1 的概率主要由「已收集的优惠券总数 $C$ 与行数 $K$ 的比值 $C/K$」决定（有限 $K$ 的修正只有 $1/K$ 量级，后面的模型辨识恰好要利用这一点点差别），所以可以离线按 $C/K$ 预先算好一组分布和对应的最优编码表，硬编码进库里。压缩和解压时，程序用 `determine_pseudo_phase(lg_k, num_coupons)` 从 Sketch 本来就有的元数据推出该用哪张表，不需要额外存储表号。

前 22 张表用来编码滑动窗口内的字节（`0..255` 共 256 个符号）。给定窗口内 8 个相邻列的置 1 概率 $q\_0, \dots, q\_7$，把各列视为独立，字节 `b` 的概率就是 8 个伯努利分布的乘积：

$$P(\text{byte} = b) = \prod\_{d=0}^{7} \begin{cases} q\_d & \text{若 } b \text{ 的第 } d \text{ 位为 } 1 \\\\ 1 - q\_d & \text{若 } b \text{ 的第 } d \text{ 位为 } 0 \end{cases}$$

上游运行时解码器用了一张 $2^{12} = 4096$ 项的查找表，透露出一个硬约束：**最大码长是 12**。用标准的 **Package-Merge 算法**（Larmore–Hirschberg, 1990）算出受限码长，按 `(码长, 符号)` 排序分配范式码字，再做一次比特反转以适配 CPC 的 LSB-first 比特流——**Gemini** 很快就把这 23 张表共 5,697 个码字分毫不差地复现了出来。

但紧接着问题就来了：`columnProbabilities.ml` 在计算第 $j$ 列的置位概率时，用的是哪个概率模型？

1. **有限 $K$ 二项模型**：$p\_j = 1/(K \cdot 2^j)$，投掷 $N$ 次后 $q = 1 - (1 - p\_j)^N$。
2. **无限 $K$ 泊松极限**：当 $K \to \infty$ 且 $N/K = \lambda$ 固定时，$q = 1 - \exp(-\lambda / 2^j)$。

只对比整数码字的话会撞上一个盲区：**在前 6 张中等密度表上，把 $K$ 从 $2^{16}$ 一直改到 $\infty$，生成的 256 个码字完全一样。** Huffman 码长是离散的阶梯函数，微小的概率变动改变不了合并顺序。

真正能当作连续「指纹」来锁定参数的，是 `generateHuffmanCodes.ml` 在每张表上方打印的两行 20 位浮点数注释，比如第 0 张字节表：

```text
// entropy:    4.4619200780464778333
// avg_length: 4.5415773046232610355; max_length = 12; num_symbols = 256
```

香农熵 $H = -\sum P(b) \log\_2 P(b)$ 和平均码长 $\sum P(b) L\_b$ 都是概率分布的**连续函数**。固定 $C/K$、把 $K$ 从 $2^{28}$ 扫到 $\infty$，对比 6 张中等密度表的香农熵与注释表头的最大绝对误差（初版测试只校验了 22 张字节表里的 2 张表头，**Claude Opus** 在 Review 时把它补全到了全部 22 张）：

| 假设的模型参数 $K$         | 6 张中等密度表的最大熵误差 $\max \lvert \Delta H \rvert$ | 6 张表的最大平均码长误差   |
| :------------------------- | :------------------------------------------------------- | :------------------------- |
| $K = 2^{28}$               | $7.38 \times 10^{-10}$                                   | $7.25 \times 10^{-10}$     |
| $K = 2^{30}$               | $1.48 \times 10^{-10}$                                   | $1.45 \times 10^{-10}$     |
| $K = 2^{31}$               | $4.92 \times 10^{-11}$                                   | $4.84 \times 10^{-11}$     |
| **$K = 2^{32}$**           | **$6.22 \times 10^{-15}$**                               | **$6.22 \times 10^{-15}$** |
| $K = 2^{33}$               | $2.46 \times 10^{-11}$                                   | $2.42 \times 10^{-11}$     |
| $K = 2^{34}$               | $3.69 \times 10^{-11}$                                   | $3.63 \times 10^{-11}$     |
| $K \to \infty$（泊松极限） | $4.92 \times 10^{-11}$                                   | $4.84 \times 10^{-11}$     |

在 $K = 2^{32}$ 处，误差骤降 4 个数量级，落进双精度浮点的舍入噪声底。

表里还有一个漂亮的对称：$K = 2^{31}$ 的误差和 $K \to \infty$ 一模一样，而 $K = 2^{33}$ 恰好是它的一半。原因是有限 $K$ 相对于泊松极限的一阶偏差严格正比于 $1/K$（推导见附录 1）。真值是 $K\_0 = 2^{32}$ 时，$2^{31}$ 和 $\infty$ 在 $1/K$ 轴上与真值的距离都是 $1/2^{32}$，而 $2^{33}$ 的距离只有一半。$2^{32}$ 也正好是上游 ICON 估计器注释里写明的 $K$ 取值范围上限。

## 二、稳态表：一个看似合理、其实不成立的「左边界截断」

接下来的 16 张稳态表（$\text{phase} = (2m+1)/32$，$C/K = B + \text{phase}$）上，发生了一次很有代表性的推理交锋。

从后面的列置换表可以确定稳态工作点的整数部分是 $B = 6$。但如果把刚锁定的 $K = 2^{32}$ 和 $B = 6$ 直接代入这 16 张表，算出的香农熵会和注释表头在小数点后第 12 位差出 **$6.1 \times 10^{-12}$**。

**Gemini 在初版 PR 里给出的解释是：** $C/K \approx 6$ 时，矩阵最左边的第 1 列还没有完全被填满（它仍为 0 的概率约为 $5.3 \times 10^{-12}$），窗口离左边界太近，受到了「左边界截断效应」的影响；于是它保持 $K = 2^{32}$ 不变，把工作点推到 $B = 32$（$C/K = 32 + \text{phase}$），误差果然降到了 $10^{-15}$。数值对上了，连 $10^{-12}$ 的量级都刚好和第 1 列的概率吻合，我第一次读的时候也觉得相当有说服力。

**Claude Opus 的消融实验把这个解释拆掉了：**

1. **保持 $B = 6$ 不动**，只把 $K = 2^{32}$ 的二项模型换成 **$K \to \infty$ 的泊松极限**——16 张稳态表的熵误差当场降到约 $10^{-14}$，回到舍入噪声的水平；
2. 保持 $K = 2^{32}$，把 $B$ 依次设为 $6, 7, 8$，最大熵误差分别是 $6.1 \times 10^{-12} \to 3.1 \times 10^{-12} \to 1.5 \times 10^{-12}$，**每把 $B$ 加 1，误差几乎正好减半**。

为什么每次减半？$B$ 加 1，窗口跟着右移 1 列（$j \to j + 1$），而二项模型相对泊松极限的修正项恰好是 $1/(2K \cdot 2^j) \propto 2^{-B}/K$。把 $B$ 推到 $32$，消除的不是什么「左边界截断」，而是把窗口推到了第 29 列附近，让有限 $K$ 修正项 $2^{-29}/2^{32} = 2^{-61}$ 小到跌破双精度精度——**无意间用有限 $K$ 的深列模拟出了 $K \to \infty$ 的泊松极限**。

那左边界到底有没有影响？这里我在初稿里写过一个错误的论证：「计算窗口字节时只读取了窗口内的 8 列，没有读左边的列，所以左边界不可能影响窗口熵。」Codex 指出这不成立：程序是先用**全部 128 列**的期望反解出 $\lambda$，再算窗口内的概率，左边界通过 $\lambda$ 间接参与了计算。正确的量级论证要用泊松模型的一个恒等式。记 $f(\lambda) = E[C]/K = \sum\_{j \ge 1} (1 - e^{-\lambda 2^{-j}})$，则

$$f(2\lambda) = f(\lambda) + 1 - e^{-\lambda}$$

也就是说，把 $B$ 加 1 时，$\lambda$ 加倍、窗口右移一列，窗口内的分布原样平移，唯一破坏这种平移不变性的是边界项 $e^{-\lambda}$。在 $C/K = 6 + 1/32$ 处 $\lambda \approx 51.93$，$e^{-\lambda} \approx 2.8 \times 10^{-23}$，对 $\lambda$ 的相对影响约 $2 \times 10^{-23}$，比 $10^{-12}$ 的残差小了十几个数量级。所以残差确实来自有限 $K$，而不是左边界。

这里还涉及一个逆向工程里很重要的概念——**可辨识性（Identifiability）**：单看这 16 张稳态表，在测试使用的 $3 \times 10^{-14}$ 比较容差下，泊松模型在 $B = 6$ 到 $84$ 之间、$K = 2^{32}$ 的二项模型在 $B = 14$ 到 $84$ 之间都能同时把全部熵和平均码长表头对到容差以内。它们并非逐位相同（彼此仍有约 $10^{-14}$ 的差别），只是在原有双精度运算和当前测试容差下区分不了；$B = 85$ 时第 7 张表的平均码长误差已达 $3.11 \times 10^{-14}$ 超过容差，再往右则 128 列的右边界会主导误差（$B = 100$ 时达到 $7.4 \times 10^{-10}$）。我们选择「$B = 6$ 的泊松极限」，是因为它和下一节的列置换表共享同一个工作点，不需要额外虚构一个 $B = 32$；但现有数据无法排除另一种写法。

## 三、列置换表：相位 `19/32` 上的一次舍入

窗口外剩下的 56 列，是通过收集罕见的「意外」状态（窗口左侧的位为 0，或窗口右侧的位为 1）并编码列号差分来压缩的。为了让编码更短，需要把**最容易出现意外的列排在最前面**，这就是 `generatePermutationsForSLIDING.ml` 生成的 16 张 56 字节列置换表。

先说清楚表的结构（我在初稿里把这几个概念混在了一起，也是 Codex 指出来的）：

- 设窗口偏移为 $\omega = \lfloor C/K - 2.375 \rfloor$，程序先把 0-based 物理列号 `col` 映射成规范化列号 `canon = (col + 56 - ω) % 64`：窗口右侧的列落在 `0 .. 56-ω`，窗口左侧的 $\omega$ 列落在 `56-ω .. 56`；
- 再按意外概率从大到小给 56 个规范化列排名次；
- 表里存的是 `encode_perm[canon] = rank`，不是按概率排好的列号序列。

从表的宏观结构能读出工作点：前 6 张表（相位 `0..5`）末尾有 3 个槽位（窗口左侧的 3 列）的名次被穿插到了序列中间，后 10 张表（相位 `6..15`）变成了 4 个。$\omega$ 在 $\text{phase} = 3/8$ 处从 $B - 3$ 跳到 $B - 2$，所以「3 变 4」意味着 $B = 6$。逐张核对也是如此：用 $B = 5, 6, 7$ 分别只能复现 6、16、10 张表。

在审查初版注释时，Claude Opus 先纠正了两处错误：初版声称列置换能佐证 $K = 2^{32}$，实际上把 $K$ 从 $2^8$ 一直拉到泊松极限，16 张表逐字节完全相同，**列置换对 $K$ 不敏感**；初版还把相位 `19/32` 上第 1 列的意外概率写成了 `1.154e-17`，按这个数排序根本拼不出原表。

更微妙的是 $p\_0$（窗口左侧的位仍为 0 的概率）的计算方式。如果图省事复用已经算好的置 1 概率 `q`，写成 **`p_0 = 1.0 - q`**，那么无论 $B = 6$ 还是 $B = 7$，都能复现 15 张表，唯独**相位 `19/32` 那张表有 4 个数对不上**。这一相位里 $\omega = 4$，几个关键列的情况如下（名次从 0 开始）：

| 规范化列号 `canon` | 物理列号（从 1 开始） | 意外概率                 | 编码名次 |
| :----------------- | :-------------------- | :----------------------- | :------- |
| 49                 | 62                    | $1.6630 \times 10^{-17}$ | 53       |
| 50                 | 63                    | $8.3150 \times 10^{-18}$ | 54       |
| 51                 | 64                    | $4.1575 \times 10^{-18}$ | 55       |
| 52                 | 1                     | $2.2211 \times 10^{-17}$ | 52       |

物理第 1 列的 $p\_0 = e^{-\lambda/2} \approx 2.22 \times 10^{-17}$ 比第 62 列的 $1.66 \times 10^{-17}$ 大，所以应当排在它前面：按概率排序的规范化列号末尾是 `..., 48, 52, 49, 50, 51`，存储的表里对应 `encode_perm[49..=52] = [53, 54, 55, 52]`。而 `1.0 - q` 会把 `52` 踢到最后，得到 `[52, 53, 54, 55]`。

问题出在舍入上。$2.22 \times 10^{-17}$ 本身完全可以用 `f64` 正常表示，不存在下溢；问题是 `q = 1 - p_0` 落在 `1.0` 附近，而 `1.0` 下方相邻浮点数的间距是 $2^{-53}$。在默认的就近舍入下，只要 $p\_0 \le 2^{-54} \approx 5.55 \times 10^{-17}$，`q` 就会被舍入成精确的 `1.0`，`1.0 - q` 得到 `0.0`，$p\_0$ 的信息在第一步就丢了，减法无从恢复——这是典型的灾难性抵消。（初稿里我把阈值写成了 $2^{-53}$，PR 的注释里也是；实际上 $p\_0$ 落在 $2^{-54}$ 到 $2^{-53}$ 之间时，结果是 $2^{-53}$ 而不是 0，同样丢光了有效数字。）

只要直接对指数求值 `(-lambda / 2^j).exp()`，$B = 6$ 就能 **16/16 全部命中**。这一处比较同时排除了 $B = 7$ 和 `1.0 - q` 两种写法；至于 Kevin 当年具体怎么写的，我们只能说「至少不是 `1.0 - q`」。

## 四、ICON：19 阶多项式与指数常数

接下来是 [`estimator.rs`](https://github.com/apache/datasketches-rust/blob/main/datasketches/src/cpc/estimator.rs) 里的 **ICON 基数估计器**。为了避免在运行时反解期望方程 $E[C] = \sum\_{j=1}^{128} K(1 - (1 - 2^{-j}/K)^N)$，Kevin 用了一个分段近似：

- 当 $C$ 不超过 $5.7K$（`lg_k >= 14` 时为 $5.6K$）时，用提取了三次前导项的 **19 阶多项式**：

$$\hat{N}\_{\text{poly}}(K, C) = C \left(1 + \frac{(C/K)^3}{66.774757}\right) \sum\_{m=0}^{19} a\_m(K) \left(\frac{C}{2K}\right)^m$$

- $C$ 更大时，切换到指数公式：

$$\hat{N}\_{\text{exp}}(K, C) = 0.7940236163830469 \cdot K \cdot 2^{C/K}$$

### 1. 多项式的拟合区间与可辨识边界

运行时在 $5.6K$ 或 $5.7K$ 就切走了，当年离线拟合用的是哪个区间？把存储好的 23 组多项式拿到阈值右侧继续求值：

- 所有行在 $C = 6K$ 以内都保持 $5 \times 10^{-7}$ 以内的相对误差，越过 $6K$ 几个百分点后迅速发散：到 $6.25K$ 时，每一行的误差都在 $4 \times 10^{-6}$ 到 $1.3 \times 10^{-4}$ 之间；
- `lg_k = 4`（$K = 16$）时边界很清楚：$C = 2..96$ 上最大误差 $8.7 \times 10^{-8}$（在 $C = 95$），$C = 96$ 处为 $1.3 \times 10^{-8}$，到 $C = 97$ 跳到 $2.2 \times 10^{-6}$；
- 但 $K$ 大时，一个整数步只对应 $C/K$ 的极小变化，看不出「悬崖」：`lg_k = 8` 在 $C = 6K + 1$ 处误差还是 $-6.6 \times 10^{-8}$，比 $C = 6K$ 处还略小。

所以「拟合区间的右端恰好是 $6K$」主要靠下面的网格实验，而不是靠误差曲线本身。至于为什么拟合区间要超出运行时阈值，「给高阶多项式留一段防端点振荡的缓冲带」是一个合理的猜测，但没有任何记录。

Claude Opus 对系数做了重建实验：

- 对 `lg_k <= 7`（$6K \le 768$），在 $C = 1, 2, \dots, 6K$ 的**每一个整数点**上做无权重最小二乘，算出的 20 个系数与上游表吻合到 `0.07% ~ 1.4%`；把左端点 `C = 1` 去掉，或者把任一端点挪动 1 个单位，吻合度就会变差 4 到 59 倍。这有力地支持了「全整数网格 $[1, 6K]$」，但不能据此断定原作者就是这么做的：权重并不确定（`lg_k = 4` 时按相对误差加权的拟合吻合得还略好一点），数值实现也无从得知。
- 初版曾猜测 `lg_k >= 8` 换成了「先稠密后几何」的采样网格，但无论用那个网格还是全整数网格，算出的系数都和原表相差 `14% ~ 65%`。从函数值反推系数，本身就是一个极度病态的问题：未缩放的 19 阶单项式基在这些网格上的二范数条件数约为 $10^{17}$（`lg_k = 4` 时为 $1.19 \times 10^{17}$，按列归一化后也还有约 $10^{14}$），函数值上看不出差别的拟合，系数可以差得很远。（初稿和 PR 注释里写的「约 $10^{12}$」是错的，也是 Codex 查出来的。）
- 顺带，Opus 把测试里的误差容差从初版宽松的 `2e-6` / `max(2e-5, 1/(80K))` 收紧到了 `3e-7` / `max(2.5e-6, 1/(80K))`。

### 2. 指数分支背后的几个常数

指数公式里的常数和上游测试里的容差，以前都被当成经验值。它们其实都能从泊松模型推出来（推导见附录 2、4）：

1. **主项 $\sqrt{2} e^{-\gamma}$**：对无穷列泊松期望做 Mellin 变换，在 $s = 0$ 的二阶极点处求留数，得到渐近展开 $E[C]/K = \log\_2 \lambda + \frac{\gamma}{\ln 2} - \frac{1}{2} + \mathcal{P}(\log\_2 \lambda) + R(\lambda)$，其中 $\mathcal{P}$ 是一个周期为 1 的微小振荡项，$R(\lambda) = \sum\_{r \ge 0} e^{-2^r \lambda}$ 在指数分支（$\lambda \gtrsim 38.5$）下按 $e^{-\lambda}$ 指数衰减，$R(\lambda) < 2 \times 10^{-17}$。忽略 $\mathcal{P}$ 和余项反解得 $\lambda \approx D \cdot 2^{C/K}$，$D = \sqrt{2} e^{-\gamma} = 0.7940236163832829\dots$，与代码里的常数在小数点后第 13 位相差 $2.36 \times 10^{-13}$。
2. **$1.09 \times 10^{-6}$ 的周期波纹**：$\mathcal{P}$ 来自虚轴上的一阶极点，它的一阶谐波让估计值产生相对振幅 $a = 2 \lvert \Gamma(2\pi i / \ln 2) \rvert \approx 1.0904 \times 10^{-6}$ 的振荡，这正是大 $K$ 下指数公式实测误差的下限。
3. **Java 测试里的 `1 / (80 * K)`**：上游 `IconEstimatorTest` 的误差上限是 `max(2e-6, 1.0 / (80 * k))`。有限 $K$ 会让指数公式轻微高估基数，相对偏差约 $1/(2K\lambda)$，在拼接点 $C = 5.7K$（$\lambda \approx 41.3$）处最大，约为 $1/(82.6K)$。`1 / (80 * K)` 与这个峰值吻合，留有约 3% 的余量；但当年为什么选这个数，没有记录。

### 3. 最后几位数字：一个能精确复现的解释

上面主项 $D$ 与代码常数之间 $2.36 \times 10^{-13}$ 的差，在 PR 和初稿里我们都列为「原因不明」。Codex 给出了一个解释：如果选择系数 $A$，让 $A \cdot K \cdot 2^{C/K}$ 相对精确反解的**相对误差在一个周期上平均为零**，那么（推导见附录 3）

$$A = \frac{D}{\left\langle e^{(\ln 2)\mathcal{P}(t)} \right\rangle} \approx D \left(1 - \frac{a^2}{4}\right) = D \left(1 - \left\lvert \Gamma\left(\frac{2\pi i}{\ln 2}\right) \right\rvert^2\right) = 0.79402361638304686\dots$$

这里的约等号是二阶展开，余项约 $5 \times 10^{-26}$，远小于 `f64` 的分辨率。舍入到 `f64` 后，**恰好就是代码里的 `0.7940236163830469`**。我复核时在 Rust 里用 `f64` 直接算这个闭式，结果与运行时常数逐位相同；用精确估计器在一个周期上数值求调和平均，也只差 2 个 ULP。这个解释现在写进了 PR 的测试。不过要强调：它证明的是「这个准则能精确解释这串数字」，并不能证明 Kevin 当年用的就是这个准则。

## 五、10 分钟重跑百万次蒙特卡罗，以及为什么随机表能精确复现整数

最后是 4 张置信区间表：`ICON_{LOW,HIGH}_SIDE_DATA` 与 `HIP_{LOW,HIGH}_SIDE_DATA`。注释里写着，它们是在真实基数 $N = 1000K$ 下各跑约 $10^6$ 次蒙特卡罗试验测出来的经验分位数：每个表项是 $10^4 \sqrt{K} \varepsilon / \kappa$，$\varepsilon$ 是估计值相对误差在 $\Phi(-\kappa)$ 处的单侧尾分位数，四舍五入为整数。

随机测出来的表无法逐位「生成」，只能重新测量。我当时很好奇：这种蒙特卡罗重测到底怎么做？如果今天重跑一次，会差多少？

老老实实模拟的话，`lg_k = 14`（$K = 16384$）时单次试验要插入 $1.6 \times 10^7$ 个元素，$10^6$ 次试验就是 $1.6 \times 10^{13}$ 次插入。Claude Opus 写的模拟器用的其实就是 Kevin 在论文附录 B 里描述过的加速思路：位矩阵的占用状态只需要用 64 个计数器 $m\_j$（每一列还剩多少个空格）表示，再另外维护 HIP 累加值和已处理的元素数。注意 HIP 累加值不能由最终的列计数推出来，它依赖发现新格子的先后顺序：比如 $K = 16$ 时在第 1、2 列各发现一个新格子，先 1 后 2 得到 $2.0323$，先 2 后 1 得到 $2.0159$。每来一个新元素，点亮新格子的概率是 $p\_{\text{hit}} = \sum\_j m\_j 2^{-j} / K$，两次点亮之间的等待元素数服从几何分布，可以一步采样跳过；点亮时 HIP 累加器加上 $1/p\_{\text{hit}}$，再按

$$\Pr(j \mid \text{命中新格}) = \frac{m\_j 2^{-j}}{K p\_{\text{hit}}}$$

选择落在哪一列。这里需要限定一下等价性：模拟器给物理第 64 列（索引 63）赋予显式权重 $2^{-64}$，并由初始 `kxp = K` 与末列兜底吸收剩余的尾质量；而在实际 `sketch.rs` 中，第 64 列会同时接住前导零数为 63 和 $\ge 64$ 的所有哈希（命中概率为 $2^{-63}$），更新 `kxp` 时仍只扣除 $2^{-64}$，且每 8 次滑动窗口偏移会重算一次 `kxp`。因此只在末列尚未命中且忽略浮点重算误差时两者与理想分布一致；不过按理想哈希估算，整轮全部试验加起来总共超过 $4 \times 10^{13}$ 次插入中，末列的期望总命中次数仅约 $4.5 \times 10^{-6}$ 次，实际几乎不会发生，对本次统计比较没有实质影响。每次试验的代价从 $O(N)$ 降到 $O(C)$；在 $N = 1000K$ 时，$C$ 约为 $10K$，步数少了约两个数量级。

由于同一批 $10^6$ 次试验同时算出某一行里的全部 6 个尾分位数（low/high × $\kappa = 1, 2, 3$），它们彼此相关，不能直接把单个格子的平方误差相加套用 $\chi^2$。为此，我们保存了全部原始样本 `C` 与 `HIP / N`：第一遍 `simA` 在 `lg_k = 4..=14` 上每行各跑 $10^6$ 次（14 线程耗时约 11 分钟）；用真实 `CpcSketch`（MurmurHash3 哈希，每行 `lg_k` 使用独立哈希流种子）在 `lg_k = 4..=7` 上各跑 $10^6$ 次作为实现对照；再用独立种子跑第二遍 `simB`（`lg_k = 4..=12`）作为零假设对照。分析时同时用两种方法计算每一行 6 个分位数的完整 $6 \times 6$ 协方差矩阵——**2000 次非参数 Bootstrap 重采样**，以及基于连续近似下分位数联合渐近正态性（用 Siddiqui 阶统计量间隔估计尾部密度 $f(Q(p))$）的解析公式——再用马氏距离平方 $T^2$ 做联合卡方检验（整体相加时以各行试验相互独立为前提）。

先看两项基础对照：`simA` 与 `simB` 未检出整体差异；真实 `CpcSketch` 对照则落在 $p \approx 0.05 \sim 0.08$ 的边缘区间（对单轮 `simA` 在 5% 阈值附近、对两轮均值略高于阈值，且单格无一超过 $3\sigma$），尚不足以认定存在系统偏差。同时，两种协方差近似在所有比较上给出的结果都高度一致：

- **同一模拟器的零假设对照（`simA` 对 `simB`，`lg_k = 4..=12`，$\text{df} = 54$）**：Bootstrap 下总 $T^2 = 62.58\ (p = 0.198)$，解析渐近协方差下 $T^2 = 63.77\ (p = 0.171)$，与两次独立百万次试验的联合起伏相符；
- **真实 `CpcSketch` 对照（`real` 对 `simA`，`lg_k = 4..=7`，$\text{df} = 24$）**：Bootstrap 下总 $T^2 = 36.72\ (p = 0.047)$，解析协方差下 $T^2 = 36.20\ (p = 0.052)$（与 `mean(simA, simB)` 对比则为 $T^2 = 34.65,\ p = 0.074$ 与 $T^2 = 33.96,\ p = 0.085$），24 个格子里没有偏离超过 $3\sigma$ 的项，超过 $2\sigma$ 的仅 1 格，未见明显的系统性偏差。

在这个校准框架下，与 Kevin 原表的比对结果分成两类：

- **ICON**：`simA` 在全部 66 格里有 **59 个与 Kevin 当年的整数一字不差**（误差在 $\pm 0.5$ 以内，符合四舍五入）；`simB` 在 `lg_k = 4..=12` 的 54 格里也有 51 格吻合（两次独立运行完全重合 49/54 格）。
- **HIP**：在假定各行独立并用均匀噪声方差 $1/12$ 近似整数舍入误差的前提下，按上游记录的试验次数计入原表自身的抽样协方差后，`Upstream` 与 `simA` 在全部 11 行（$\text{df} = 66$）上的总 $T^2 = 103.97\ (p = 1.99 \times 10^{-3})$（解析协方差下 $T^2 = 102.27,\ p = 2.81 \times 10^{-3}$）；独立对照 `Upstream` 与 `simB`（`lg_k = 4..=12`，$\text{df} = 54$）的总 $T^2 = 73.46\ (p = 0.040)$（解析协方差下 $73.04,\ p = 0.043$），`Upstream` 与 `mean(simA, simB)`（$\text{df} = 54$）则为 $87.29\ (p = 2.77 \times 10^{-3})$（解析协方差下 $86.36,\ p = 3.39 \times 10^{-3}$）。可以看出整体上确实存在小幅但可检出的不一致信号，其中 **`lg_k = 7, 9, 11`** 在 `simA` 里贡献了最多信号（单行 $p$ 值为 $5.4 \times 10^{-3}$、$0.014$ 和 $9.5 \times 10^{-4}$，但按 11 行做 Holm 多重比较校正后，只有 `lg_k = 11` 以 $0.010$ 稳稳通过，`lg_k = 7` 约 $0.054$、`lg_k = 9` 约 $0.13$；而在独立的 `simB` 中这三行的单行 $p$ 值则分别为 $0.092$、$0.066$ 与 $0.167$）。因此，我们有理由怀疑整体存在轻微差异，但各行证据强弱不一，尚不足以断言 `7, 9, 11` 三行都存在确定性的系统偏移。从数值大小看，全部 66 格的最大绝对差为 83.74 个单位（位于 `lg_k = 9` 低侧 $\kappa = 3$），相当于误差因子 $\varepsilon$ 的相对变化不超过 **1.49%**（换算成该单侧置信区间宽度变化约为 **1.61%**），对区间数值大小的影响很小（不过我们未另行重测实际覆盖率是否受到影响）。

为什么一组随机试验测出来的 ICON 表，会在九成格子里连个位数都一样？因为 **ICON 估计值只依赖整数 $C$**，它的任何分位数都只能落在一个个离散的「台阶」上。$C$ 每加 1，表项跳一个台阶，间距约为

$$\Delta\_{\text{atom}} \approx \frac{10^4 \ln 2}{\sqrt{K} \kappa}$$

`lg_k = 4, kappa = 1` 时相邻台阶相差约 1733。台阶并不严格等宽：在指数区，相邻台阶的精确间距是 $\frac{10^4 \sqrt{K}}{\kappa} \frac{\hat{N}(C)}{N} (2^{1/K} - 1)$，上式只是它的近似。只要两次实验的经验分布在跨过目标分位数时落在同一个整数 $C$ 上，算出来的值就精确相等。剩下 7 个不一致的格子，我逐个找到了双方对应的 $C$：Kevin 的 7 个值同样落在台阶上（都在某个整数 $C$ 的表值 $\pm 0.5$ 以内），只是和我们落在不同的 $C$ 上，相差 1 个 $C$ 的有 5 格，相差 2 个和 3 个的各 1 格。以 `lg_k = 7, kappa = 1` 的高侧为例，我们的分位数落在 $C = 1329$，表值 $6806.33$；Kevin 的 7458 对应 $C = 1330$，表值 $7457.61$。HIP 严格说在有限 $N$ 下也是离散的，只是取值密集得多，不会出现这种整数级的重合。

需要说明的是，这部分模拟器和原始结果目前没有放进 PR，只是这次调研的实验记录。

## 六、证据的边界，与留给未来的 6 个问题

这轮接力下来，生成器、解析常数和测试加固一共整理成了 15 个提交，都在 [`apache/datasketches-rust` PR #355](https://github.com/apache/datasketches-rust/pull/355) 里，目前还在 Review 中。

Codex 那一轮审查对 PR 本身也有实质贡献。它做了两个变异实验：把运行时常数改成 `0.794024`，或者把 4 张置信表的 132 个数全部清零，原有的测试居然都能通过——前者是因为常数测试比较的是测试里另抄的一份常量，后者是因为置信区间测试只检查了上下界夹住估计值。我复核确认后补了两个提交：常数测试改为直接从生产函数读取系数，与上面的闭式比对；置信区间测试增加了「区间随 $\kappa$ 严格变宽」的检查，并在注释里写明它不验证表值本身。另外几个提交修正了 PR 注释里的舍入阈值、条件数、等价区间上界（`B = 84`）和几处过度推断。Codex 还两次对文章和统计分析做复查，提醒了相关分位数协方差、真实哈希流跨行独立性、多重比较和区间宽度非线性换算等细节，让我们能一路把论证和实验收紧到现在这个版本。Huffman 和列置换的逐位重建测试，则一直是实打实的验证。

做这种历史遗留代码的反推，最容易犯的错是「测试跑通了，就以为自己还原了原作者的想法」。Codex 的总结说得很准确：**证明一种方法能解释数据，与证明原作者实际使用了这种方法，是两件事。** 所以我们在代码注释里，把「已被观测数据唯一锁定的参数」和「存在观测等价类、现有证据无法区分的部分」严格分开，并把下面这些问题留给社区：

1. **稳态字节表的原始写法**：直接用了泊松极限，还是用有限 $K = 2^{32}$ 但把工作点推到了 $B = 14$ 到 $84$ 之间？在原有双精度运算和当前测试容差（$3 \times 10^{-14}$）下，两者无法区分。
2. **Package-Merge 的平局规则**：65 符号表在 $P(62) = P(63) + P(64) = 2^{-63}$ 处有一次精确的权重平局，但叶子优先和合并包优先生成的码长完全一致，表里看不出来。

## 附录：几个解析推导

### 1. 为什么有限 $K$ 的熵误差正比于 $1/K$？

在第 $j$ 列上，设 $x = 1/(K \cdot 2^j) \ll 1$，二项模型对数生存概率的泰勒展开为：

$$\ln(1 - q\_{\text{bin}}) = N \ln(1 - x) = -N\left(x + \frac{x^2}{2} + O(x^3)\right) = -\frac{N}{K 2^j}\left(1 + \frac{1}{2 K 2^j} + O(K^{-2})\right)$$

对比泊松极限 $\ln(1 - q\_{\text{poi}}) = -\lambda / 2^j$，有限 $K$ 相当于在每一列的指数上乘了修正因子 $1 + \frac{1}{2 K 2^j}$。该因子随列号 $j$ 按 $2^{-j}$ 衰减，调整全局的 $\lambda$ 无法同时抵消 8 个窗口列上的偏差，残余的列概率扰动 $\delta q\_j = O(2^{-j}/K)$ 使香农熵产生 $\Delta H = \alpha / K + O(K^{-2})$ 的线性偏移。

### 2. 主项 $\sqrt{2} e^{-\gamma}$ 与周期波纹的 Mellin 变换推导

对 $f(\lambda) = \sum\_{j=1}^{\infty} (1 - e^{-\lambda 2^{-j}})$ 做 Mellin 变换 $f^*(s) = \int\_0^\infty f(\lambda) \lambda^{s-1} d\lambda$。在收敛带 $-1 < \Re(s) < 0$ 内有 $\int\_0^\infty (1 - e^{-x}) x^{s-1} dx = -\Gamma(s)$（取 $s = -1/2$ 检查：被积函数为正，而 $-\Gamma(-1/2) = 2\sqrt{\pi} > 0$），因此：

$$f^*(s) = -\Gamma(s) \sum\_{j=1}^{\infty} 2^{js} = -\Gamma(s) \frac{2^s}{1 - 2^s}$$

（初稿漏掉了这个负号，是 Codex 指出的。）将逆变换的积分路径向右平移，跨过 $\Re(s) = 0$ 上的极点后，在 $\lambda \to \infty$ 时得到渐近展开 $f(\lambda) = \log\_2 \lambda + \frac{\gamma}{\ln 2} - \frac{1}{2} + \mathcal{P}(\log\_2 \lambda) + R(\lambda)$，其中指数衰减余项为 $R(\lambda) = \sum\_{r \ge 0} e^{-2^r \lambda}$（指数分支下 $\lambda \gtrsim 38.5$ 时 $R(\lambda) < 2 \times 10^{-17}$）：

- **$s = 0$ 处的二阶极点**：展开 $\Gamma(s) = \frac{1}{s} - \gamma + O(s)$ 与 $\frac{2^s}{1 - 2^s} = -\frac{1}{s \ln 2} - \frac{1}{2} + O(s)$，留数给出主项 $\log\_2 \lambda + \frac{\gamma}{\ln 2} - \frac{1}{2}$。令其等于 $C/K$，解得 $\lambda \approx \sqrt{2} e^{-\gamma} 2^{C/K}$。
- **$s\_k = \frac{2\pi i k}{\ln 2}$（$k \neq 0$）处的一阶极点**：给出周期为 1 的振荡项

$$\mathcal{P}(t) = -\frac{1}{\ln 2}\sum\_{k \neq 0} \Gamma\left(\frac{2\pi i k}{\ln 2}\right) e^{-2\pi i k t}$$

其中一阶谐波（$k = \pm 1$）主导。换算成 $\lambda$ 的相对振幅（乘以 $\ln 2$）为：

$$a = 2\left\lvert\Gamma\left(\frac{2\pi i}{\ln 2}\right)\right\rvert = 2\sqrt{\frac{\pi}{y \sinh(\pi y)}} \approx 1.0904 \times 10^{-6}, \quad y = \frac{2\pi}{\ln 2}$$

### 3. 「周期平均相对误差为零」给出的系数

忽略指数余项 $R(\lambda)$，由 $C/K \approx \log\_2 \lambda + \frac{\gamma}{\ln 2} - \frac{1}{2} + \mathcal{P}(t)$（$t = \log\_2 \lambda$）可得 $\lambda \approx D \cdot 2^{C/K} e^{-(\ln 2)\mathcal{P}(t)}$。近似式 $A \cdot 2^{C/K}$ 的相对误差为 $\frac{A}{D} e^{(\ln 2)\mathcal{P}(t)} - 1$，令它在一个周期上的平均值为零：

$$A = \frac{D}{\left\langle e^{(\ln 2)\mathcal{P}(t)} \right\rangle}$$

$(\ln 2)\mathcal{P}(t)$ 的一阶谐波近似为 $a \cos(2\pi t + \phi)$，其均方值为 $a^2/2$，于是 $\langle e^{(\ln 2)\mathcal{P}} \rangle \approx I\_0(a) = 1 + a^2/4 + a^4/64 + \cdots$（$I\_0$ 是零阶修正贝塞尔函数），$A \approx D(1 - a^2/4)$。由于 $a^2/4 \approx 3 \times 10^{-13}$，$D/I\_0(a)$ 与 $D(1 - a^2/4)$ 只差约 $5 \times 10^{-26}$，高次谐波的贡献更小，都远低于双精度精度。按 $C/K$ 而不是按 $t$ 取平均，结果完全相同：$dC/K = (1 + \mathcal{P}'(t))\,dt$，而 $\int\_0^1 e^{(\ln 2)\mathcal{P}(t)} \mathcal{P}'(t)\,dt = 0$。

### 4. 拼接点有限 $K$ 偏差 $\frac{1}{82.6K}$

有限 $K$ 下达到相同 $C/K$ 所需的真实 $\lambda$ 比无限 $K$ 略低，指数公式在拼接点 $C = 5.7K$（$\lambda\_{\text{splice}} \approx 0.794 \times 2^{5.7} \approx 41.3$）处的相对高估为：

$$\frac{\Delta \hat{N}}{N} \approx \frac{1}{2 \lambda\_{\text{splice}} K} \approx \frac{1}{82.6 K}$$

### 5. ICON 与 HIP 的渐近相对标准误

$\lambda \gg 1$ 时，泊松模型下各格子独立，$\operatorname{Var}(C) \approx K \sum\_{j} e^{-\lambda 2^{-j}}(1 - e^{-\lambda 2^{-j}})$。对周期取平均后化为 **Frullani 积分**：

$$\frac{\operatorname{Var}(C)}{K} \approx \frac{1}{\ln 2}\int\_0^\infty \frac{e^{-u} - e^{-2u}}{u} du = 1 \implies \operatorname{sd}(C) \approx \sqrt{K}$$

- **ICON**：由 $\hat{N}\_{\text{ICON}} \propto 2^{C/K}$ 和误差传播，$\operatorname{RSE}(\hat{N}\_{\text{ICON}}) \approx \frac{\ln 2}{K} \operatorname{sd}(C) = \frac{\ln 2}{\sqrt{K}}$，对应 `ICON_ERROR_CONSTANT = ln 2`。
- **HIP**：在 $\lambda = n/K$ 时，下一个新元素改变 Sketch 的概率为 $p \approx \frac{1}{\lambda \ln 2}$。对条件方差积分：

$$\operatorname{Var}(\hat{N}\_{\text{HIP}}) \approx \int\_0^N \left(\frac{1}{p} - 1\right) dn \approx \frac{\ln 2}{2} \frac{N^2}{K} \implies \operatorname{RSE}(\hat{N}\_{\text{HIP}}) \approx \sqrt{\frac{\ln 2}{2}} \frac{1}{\sqrt{K}}$$

对应 `HIP_ERROR_CONSTANT = 0.5887050112577373`。
